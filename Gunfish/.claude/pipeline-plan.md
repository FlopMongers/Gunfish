## Goal

Move `GunfishRenderer` from a plain C# class constructed externally (by `Gunfish.Spawn` at runtime and `GunfishPrefabBaker.BakeFish` at bake time) into a `MonoBehaviour` living directly on the fish body's root segment. This makes the body self-sufficient for its own line rendering instead of depending on the `Gunfish` component (which lives on the persistent `Player` object, not on the body) to drive `Render()` every frame.

This is a follow-up to the "editor-time baked fish prefabs" migration. The user found that a baked prefab's `LineRenderer` shows all-zero positions when viewed outside Play mode or dropped standalone into a scene, because nothing calls `Render()` until `Gunfish.Update()` runs at runtime. Converting `GunfishRenderer` to a `MonoBehaviour` with its own `Update()`, and calling `Render()` once immediately inside `Init()`, fixes this: segments have real positions by the time `Init()` runs (either just-generated by `GunfishGenerator` during baking, or already positioned from the baked prefab at runtime), so `transform.hasChanged` is true for every segment and `Render()` populates every `LineRenderer` position right away — no Play mode required.

Replace the entire file contents with:

```csharp
using System.Collections.Generic;
using UnityEngine;

public class GunfishRenderer : MonoBehaviour {
    public LineRenderer LineRenderer { get; private set; }
    private List<GameObject> segments = new List<GameObject>();

    public void Init(float widthMultiplier, Material material, List<GameObject> segments) {
        this.segments = segments;

        LineRenderer = gameObject.CheckAddComponent<LineRenderer>();
        LineRenderer.positionCount = segments.Count;
        LineRenderer.material = material;
        LineRenderer.sortingLayerName = "Fish";
        LineRenderer.widthMultiplier = widthMultiplier;

        Render();
    }

    void Update() {
        Render();
    }

    public void Render() {
        for (int i = 0; i < segments.Count; i++) {
            var segment = segments[i];
            if (segment == null || !segment.transform.hasChanged)
                continue;
            LineRenderer.SetPosition(i, segment.transform.position);
        }
    }
}
```

Notes:
- Drop the now-unused `using System.Collections;` line (not used by the new body either).
- `Segments` public property is replaced by a private `segments` field (no longer needs to be externally readable; only `LineRenderer` is read externally, per Gunfish.cs's `gunfishRenderer.LineRenderer.material...` usage).
- The constructor is gone; Unity does not invoke custom constructors on MonoBehaviours. `Init(...)` replaces it and additionally calls `Render()` once at the end (the actual bug fix).
- `LineRenderer` is now added via `gameObject.CheckAddComponent<LineRenderer>()` (the GameObject this component lives on) rather than `segments[0].CheckAddComponent<LineRenderer>()`, since this script itself now lives on `segments[0]` (the root segment).
